### 1.2. 目的
コンビニ店舗でのレジ業務をデジタル化し、商品スキャンから会計確定・レシート出力までの基本的なPOS操作を実現する。

### 1.3. 解決する課題
- 手計算による会計ミスの防止
- 税率（軽減税率8% / 標準税率10%）の正確な適用と集計
- 取引データの自動DB保存による業務効率化
- レシート自動出力による紙面業務の削減

## 2. ユーザージャーニー

### 2.1. 想定ユーザー
- コンビニ店舗のレジ担当者（店員）
- 一人のレジに一人のオペレーターが同時操作する

### 2.2. 基本操作フロー
1. 店員が商品のバーコードをスキャン（または手動入力）
2. カート一覧に商品が追加され、税率・数量・小計が自動表示される
3. 複数商品を連続スキャンし、合計金額がリアルタイムに更新される
4. 金額を確認し、預かり金額を入力
5. お釣りが自動計算される
6. 「会計確定」ボタンを押して取引を保存し、レシートを出力
7. 画面がリセットされ、次の取引に備える

## 3. 業務上の目的

| 目的 | 説明 | KPI（指標） |
|------|------|------------|
| **会計精度の確保** | 税率別の消費税計算を自動化し、端数処理（切り捨て）を正確に実行する | 計算誤差 0件 |
| **業務効率化** | バーコード入力1回で商品登録・計算・表示を一気通貫で行う | 1取引あたり所要時間の短縮 |
| **記録の自動化** | 取引データをDBに自動保存し、後続の売上集計・在庫管理の基盤を構築する | 手動入力ミスの解消 |
| **コンプライアンス** | 日本の消費税法に準拠した軽減税率（8%）と標準税率（10%）の明確な区別と表示 | 税務署への報告精度 |

## 5. 受け入れ基準

| ID | 基準 |
|----|------|
| AC-1 | バーコード入力で既存商品が正しくカートに追加されること |
| AC-2 | 同一商品を2回スキャンした場合、数量が2になること |
| AC-3 | 存在しないJANコード入力時にエラーが表示されること |
| AC-4 | 軽減税率（8%）商品の税込小計が「単価 × 数量 × 1.08」の端数切り捨てで計算されること |
| AC-5 | 標準税率（10%）商品の税込小計が「単価 × 数量 × 1.10」の端数切り捨てで計算されること |
| AC-6 | 8%と10%が混在するカートで、税率別集計が正しく行われること |
| AC-7 | 消費税の端数処理がすべて切り捨て（Floor）で行われること |
| AC-8 | 預かり金額入力時に即座にお釣りが計算表示されること |
| AC-9 | 預かり金額が合計未満の場合、会計確定ボタンが無効化されること |
| AC-10 | 会計確定後に取引データがDBに保存されること |
| AC-11 | 会計確定後に画面がリセットされ、次の取引が可能されること |
| AC-12 | レシートテキストファイルがデスクトップに正しく出力されること |
| AC-13 | 数量変更時に全金額がリアルタイムに再計算されること |

## 7. スコープ外（MVP対象外）

| 項目 | 理由 | 将来優先度 |
|------|------|-----------|
| 支払方法選択（クレジット/電子マネー） | MVPは現金のみ | 中 |
| モーダル画面 | MVPは画面内完結 | 低 |
| 在庫管理・売上レポート | MVPは取引記録に集中 | 中 |
| ユーザー認証・権限管理 | 単一ユーザー前提 | 低 |
| ネットワーク通信・複数レジ対応 | シングルレジ前提 | 高 |
| データバックアップ・リストア | 運用フェーズで対応 | 中 |
