## 2. 設計方針

### 2.1. なぜサービス層を分離するのか

- **テスト容易性**: データベースアクセスを抽象化し、単体テストでモックを使用できる
- **責務分離**: 画面ロジックはUIロジックと計算に専念し、DB操作はサービス層が担当
- **将来拡張性**: サービス実装を変更しても画面ロジックに影響しない

### 2.2. 依存関係の原則

- 画面ロジックは具象クラスではなく**インターフェース**に依存する
- インターフェースと実装の両方をサービスフォルダに配置する
- テストではモックオブジェクトを注入して、DB接続なしにテスト可能にする

## 3. サービス一覧

| サービス名 | 役割 |
|-----------|------|
| バーコードサービス（インターフェース） | バーコードによる商品検索のインターフェース |
| バーコードサービス（実装） | バーコード検索の実装（DB接続） |
| 取引サービス（インターフェース） | 取引保存を行うインターフェース |
| 取引サービス（実装） | 取引保存の実装（DB接続） |
| レシートサービス（インターフェース） | レシート生成・保存を行うインターフェース |
| レシートサービス（実装） | レシート生成・保存の実装 |

## 4. サービスインターフェース定義

### 4.1. バーコードサービス

| メソッド | 入力 | 出力 | 動作 |
|----------|------|------|------|
| 商品検索 | バーコード文字列、キャンセルトークン | 商品情報（存在しなければなし） | JANコードに合致する商品をDBから検索し、存在しなければなしを返す |

### 4.2. 取引サービス

| メソッド | 入力 | 出力 | 動作 |
|----------|------|------|------|
| 取引保存 | 合計金額、消費税額、取引明細一覧、キャンセルトークン | 保存された取引情報 | 取引データと取引明細をDBに保存する |

### 4.3. レシートサービス

| メソッド | 入力 | 出力 | 動作 |
|----------|------|------|------|
| レシート生成 | レシート情報（取引ID、日時、明細、金額等） | レシートテキスト | レシートレイアウトに基づいてテキストを生成する |
| レシート保存 | 取引ID、レシートテキスト、キャンセルトークン | なし | レシートをファイルに保存する |

## 5. 例外処理方針

- DB接続エラーが発生した場合、例外は呼び出し元（画面ロジック）に伝播する
- MVP では例外ハンドリングは画面ロジック側で例外捕捉により行う

## 6. 依存関係の注入（DI）方針

### 6.1. DI方針
- 画面ロジックはウィンドウの生命周期と同一であるため、全サービスをシングルトンで登録する
- DB コンテキストはファクトリパターンで毎操作ごとに短寿命インスタンスを生成し、スレッドセーフ性とライフタイム問題を回避する

### 6.2. 本番環境での利用
- ログ機能を有効にする
- DBファクトリを登録する
- バーコードサービス、取引サービス、レシートサービスをシングルトンで登録する
- 画面ロジックをシングルトンで登録する

### 6.3. テスト環境での利用
- 各サービスのモックを作成し、画面ロジックに注入する

### 6.4. DI コンテナの採用

| 理由 | 説明 |
|------|------|
| テスト容易性 | モック注入による単体テストが容易 |
| 切り離し容易性 | サービス実装の変更が画面ロジックに影響しない |
| 拡張性 | 新規サービス追加時に DI 登録のみで対応可能 |

## 7. データフロー図（サービス層含む）

```
[画面] 
    | バーコード入力 / 預かり金額入力 / ボタン操作
    v
[画面ロジック] --バインディング--> [データ]
    |
    ├──> バーコードサービス.商品検索()
    |         |
    |         v
    |    [バーコードサービス実装] ──> [DBコンテキスト] ──> [DB]
    |         |
    |         └── 商品情報を返却
    |
    ├──> カートに商品を追加/数量更新
    ├──> 合計再計算
    |
    └──> 取引サービス.取引保存()
              |
              ├──> 取引サービス.取引保存()
              |         |
              |         v
              |    [取引サービス実装] ──> [DBコンテキスト] ──> [DB]
              |         |
              |         └── 取引情報を返却
              |
              └── レシート出力 → デスクトップ
```

## 8. テストカバレッジ

### 8.1. テスト方針

- 単体テスト: モックを使用したサービス呼び出しテスト
- 統合テスト: 実際の DB との接続テスト
